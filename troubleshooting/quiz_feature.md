***Problem: Score Always Showing 0***
**Cause:**

The submitted answer values from the HTML form (1, 2, 3, 4) were not matching the stored correct answers because:

Correct answer in quiz_data was stored as a 0-based index (e.g., 0 for first option).

User was entering 1-based values.

Sometimes, users might enter the actual text instead of a number.

**Solution:**

Normalized the user’s input before comparison:

If input was a digit → converted to int(input) - 1 to match the stored index.

If input was text → compared case-insensitively with the correct option text.

**Learning:**

Input normalization is critical — always account for differences in format, indexing, and case sensitivity when comparing user input to stored answers.

***2️⃣ Problem: KeyError: 'answer' in Form Data***
**Cause:**

Code was trying to access request.form['answer'] directly, but each question’s field had a different name (answer_0, answer_1, etc.).

Some questions were left unanswered, leading to missing keys in the form data.

**Solution:**

Used request.form.get(f'answer_{i}') to safely fetch each answer without throwing errors.

Added a check for unanswered questions before processing.

**Learning:**

Never directly index into form data without a .get() fallback when handling dynamic or optional fields.

***3️⃣ Problem: Storing Quiz Data in MySQL for Multiple Users***
**Cause:**

Initially, there was no way to distinguish between quizzes taken by different users.

Without a unique quiz_no per user, all quiz attempts risked mixing together in the database.

**Solution:**

Added user_id from the session to every DB insert.

Created a function to get the next quiz number per user by querying MAX(quiz_no) in the database and incrementing it.

**Learning:**

When storing user-specific data, always include a unique identifier (user_id) and context metadata (like quiz_no) to separate different attempts.

***4️⃣ Problem: Keeping Original app.py Structure While Adding DB Features***
**Cause:**

Adding MySQL inserts could have broken the existing quiz logic if not integrated carefully.

Needed to keep the score calculation logic exactly as it was, but extend it to also store answers.

**Solution:**

Inserted the DB write operation after the score calculation loop, so the correctness logic remained intact.

Made sure all required quiz details (question, options, correct answer, user’s answer) were passed into the DB insert statement.

**Learning:**

When enhancing existing code, separate the core logic from new features and integrate in a way that doesn’t change the working behavior.

***5️⃣ Problem: Handling AI-Generated Quizzes***
**Cause:**

The quiz was generated by AI, meaning:

The format of questions and answers wasn’t always consistent.

Some questions might not have options (open-ended).

**Solution:**

Added checks:

If options exists → treat as multiple choice.

If options missing → treat as open-ended question.

**Learning:**

When working with dynamically generated content, always validate and normalize the structure before using it.

***✅ Overall Learnings:***

Validate and normalize all incoming data before comparison or storage.

Never assume form fields are always present — use .get() with safe defaults.

Always store metadata (like user_id and quiz_no) in multi-user apps to prevent data collisions.

Integrate new features without breaking existing logic — keep calculation and persistence concerns separate.

AI-generated data needs extra validation layers because its structure can vary.
